# 签到台 · Auto Check-In

一个面向个人使用的多站点、多账号自动签到工具。Go 核心、Vue 3 界面、SQLite 存储；Windows 独立应用窗口和 Docker 网页共用一套业务逻辑。

**已发布成品：** [最新 Release 的 Windows、Docker 离线包及校验和](https://github.com/sck03/auto-check-in/releases/latest)。源码版本以 [`internal/buildinfo/VERSION`](internal/buildinfo/VERSION) 为准；main 的修改不等于已经发布新版本。

镜像：`docker pull ghcr.io/sck03/auto-check-in:latest`（linux/amd64、linux/arm64；需要固定版本时使用 Release 对应标签）。

## 已实现

- 站点与账号管理，四种平台模板按专用站点和通用模板分组，支持接口与网页按钮签到。
- 北京时间 **08:00–09:00** 按账号分别随机首次执行，**每天确认成功一次**。
- 明确的临时故障默认最多重试 2 次，约等待 5 / 15 分钟并随机延后 0–30 秒；补签默认截止 **09:00**。
- 验证码、登录失效与结果不明分别处理；New API 支持只读签到状态复核。
- Windows 独立浏览器登录窗口，可直接输入、授权和处理验证码；网页预览支持直接输入与 OAuth 新页面跟随，再保存账号独立会话。
- AES-256-GCM 凭据存储、口令加密备份、持久任务队列、异常退出恢复和历史记录。
- Windows 托盘、最小化到托盘、关闭窗口后继续运行、登录 Windows 后自动启动及托盘右键菜单。
- 单个后台浏览器进程、最多两个隔离会话、空闲 60 秒释放；隐藏界面停止轮询。

当前源码 1.0.7 修复网页密码会话复用、跨日限流、备份容量不一致和带查询参数的 OAuth 登录路径，并优化连接复用与条件刷新；实现与验证范围见 [本轮维护记录](docs/maintenance-20261025.md)。各站点规则如下：

| 站点 | 每日操作 |
| --- | --- |
| AnyRouter | 北京时间 08:00 后访问已登录页面并确认身份，不调用签到接口 |
| AgentRouter | 北京时间 08:00 后重新登录，不调用退出接口，不点击签到 |
| 薄荷 API | 在 `https://up.x666.me` 保存 LinuxDO 登录会话；查询今日状态后执行一次免费抽奖，奖励直接到账 |
| New API（通用） | WONG 等兼容站点默认使用接口签到；网页按钮签到可自动识别常见按钮，CSS 选择器可选 |

前三项归为“专用站点”，New API（通用）合并原 New API、WONG 和自定义网页签到入口。接口签到使用模板的已知接口并检查今日状态，兼容 New API 和 WONG 的状态字段。网页按钮签到在指定页面识别常见中英文签到按钮，或使用配置的 CSS 选择器；只有出现明确签到结果才确认完成，多个候选按钮时停止并提示。网页按钮调用网站自身的请求，不会遍历或猜测未知接口，也不保证任意网站都能自动识别。默认 HTTP 执行占用较低；OAuth 登录或站点验证可选择浏览器执行，网页按钮签到必须使用浏览器。没有账号引用的站点可切换平台模板和签到方式。

密码登录一般不需要先手动登录：有效会话会被复用，失效时才提交密码。GitHub / LinuxDO 账号会自动选择对应入口，并继续处理能确认属于本站的授权确认页，包括 LinuxDO 的“允许”链接。AgentRouter 会等待站点 OAuth 配置加载完毕再点击，避免按钮先显示、应用 ID 尚未就绪时打开错误授权页。入口检测与点击分离，授权响应延迟时不重复提交。验证码、二次验证需通过“浏览器登录”处理；OAuth 注册账号可能尚未设置本站密码。薄荷主站与签到页面的凭据独立，不能用主站 Cookie 替代签到页面的 `userToken`。

执行详情包含失败阶段、HTTP 状态、站点原因和处理建议。Windows 人工登录及 AgentRouter OAuth 自动执行使用独立的普通可见浏览器窗口，结束后关闭；不连接日常浏览器配置，不发送会使导入会话失效的退出请求。Cloudflare 放行仍取决于真实站点、浏览器和网络环境。08:00 前的特殊站点测试不会占用当天正常计划。

AgentRouter 的个人设置页是 `/console/personal`，用户信息接口仍是 `/api/user/self`。保存会话时，若已捕获本次登录成功响应、当前页面用户 ID 一致且存在会话 Cookie，就无需再次请求可能被验证页拦截的用户信息接口；旧缓存本身不能作为登录成功证据。

只有 AgentRouter 每次清理本站旧会话以触发重新登录。AnyRouter、兼容 New API 的站点保留并优先复用有效会话；只有明确失效才重新登录，按账号配置选择 LinuxDO / GitHub 并继续授权。此时会移除阻止登录页显示的失效页面用户标记，保留 Cookie；临时故障、限流或验证页面不会触发重新登录。

默认自动任务和补签均在 09:00 截止，正在执行的自动任务也受此截止时间约束。保存登录、取消登录或签到结束后会关闭账号页面和授权弹窗，空闲时不访问站点；空的后台浏览器进程最多保留 60 秒供临近任务复用。

**保存 Cookie 会影响平时的浏览器登录吗？** 程序使用独立浏览器目录与账号会话，不修改日常浏览器的 Cookie，也不主动请求退出登录。普通站点只有明确会话失效才重新登录，临时故障和验证页面不会触发重复登录。但网站的单会话限制、Token 轮换、IP/设备风控仍可能使旧登录失效；AgentRouter 每日重新登录的规则也受网站策略约束。

**签到成功后会一直运行吗？** 当天确认完成后不再自动访问该账号，调度器按最近任务时间阻塞等待；新任务、设置或会话变化会即时唤醒。没有每小时维护，历史清理只在启动时和每天北京时间零点执行；系统恢复或时间变化通过系统通知重新核对计划。收起到托盘后停止窗口检测和定时菜单刷新，并释放管理窗口浏览器。主服务仍常驻并占少量内存；退出程序、关机或系统睡眠期间无法执行任务，恢复后按当日窗口处理到期任务。

管理界面空闲时每 30 秒刷新，任务进行中每 5 秒刷新，手动操作和重新显示窗口会立即刷新；隐藏界面停止轮询。

账号、站点和设置支持 ETag 条件读取，未变化时返回 304，复用当前登录内的快照；退出或更换管理令牌会清除快照。网页按钮的密码 / OAuth 账号先只读检查签到页面，可直接操作时复用会话，仅识别到登录表单或入口时才重新登录。查询参数保留在登录导航中，页面与登录响应识别按解析后的路径判断。

写入完成后的刷新由应用统一接收，保存或执行期间切换页面仍会更新账号与记录；浏览器输入和备份导出不会触发无关的工作区刷新。

账号已绑定用户 ID 后，身份不匹配会停止执行并保留原凭据。结果写入失败使用独立截止时间重试；仍不可写时只恢复本地记录，不重复访问站点。数据库恢复后账号转为待核对，重启也会保留中断语义。同站点任务等待时保留在队列中，其他站点可继续执行。

奖励金额来自站点响应，不固定为 $25；余额差额不会被当作签到奖励。验证包含本地模拟站点和 AgentRouter 真实账号，具体结果见 [进度与验收](docs/progress.md)。

## Windows 直接运行

使用发布目录中的 `AutoCheckIn.exe`。运行设备需要已安装 Edge 或 Chrome；用户不需要 Go、Node 或 Python。

从 v1.0.1 起，程序压缩包只包含可执行文件、简短 `README.md` 和单个 `THIRD_PARTY_NOTICES.md`。完整文档保留在仓库，依赖版本及完整许可文本合并到声明文件中，不再附带 `docs/` 或 `licenses/` 文件夹。

1. 双击 `AutoCheckIn.exe`，打开独立管理窗口。
2. 在“站点管理”中确认站点地址，在“账号签到”中添加账号。
3. 使用“浏览器登录”绑定会话，或填写账号凭据。AgentRouter 请选择密码或 OAuth 登录。
4. 手动执行一次并核对记录，再保留自动计划运行。

默认数据目录为 **`AutoCheckIn.exe` 所在目录下的 `data`**，数据库是 `data/checkin.db`；密钥、托盘设置和浏览器临时目录也保存在这里。设置页“运行环境”显示实际数据目录。程序放在 D/E 盘时，应用数据也保存在相应磁盘；该目录必须可写，不会因写入失败自动回退到系统盘。

**为什么旧版 `data/desktop-browser` 接近 500 MB？** 它是管理窗口使用的 Edge / Chrome 配置目录，浏览器会下载组件、模型和媒体模块；这些并非签到必需数据。当前版本仅对管理窗口关闭组件更新、后台联网、同步与扩展，设置网页磁盘缓存目标 8 MiB、媒体缓存目标 1 MiB；这两个值不是整个目录的硬上限。启动时回收旧目录，窗口关闭或收起托盘后删除临时配置；异常退出留下的目录在下次打开时回收。本机实测旧目录约 497 MiB，优化后窗口运行期间约 21 MiB，关闭后目录消失；实际大小随浏览器版本变化。账号会话仍保存在加密数据库中，独立登录窗口保持原有浏览器参数。

当前数据库格式为 v6，已有 v5 数据会在事务内升级，保留账号、加密凭据和历史，并从近期记录恢复仍有效的限流时间；升级失败整体回滚。v1–v4 及更高未知版本仍拒绝打开。默认端口及旧 localStorage origin 会自动归一化，不从系统缓存目录导入。新安装可使用 `-data` 或 `CHECKIN_DATA_DIR` 指定目录。升级后的数据库请使用 1.0.7 或后续兼容版本；跨设备迁移可使用加密备份。

设置页可控制托盘和开机运行。开机运行默认关闭，启用后在**当前用户登录 Windows 后**直接驻留托盘。程序退出后不会执行计划；睡眠和关机期间也不会执行。

托盘右键提供：显示主窗口、立即签到全部、暂停/恢复自动计划、开机运行、最小化到托盘、关闭窗口后继续运行、打开数据目录、退出签到台。点击或双击托盘图标可以恢复窗口。

另有 `checkin-server.exe`，适合独立常驻服务：

```powershell
.\checkin-server.exe -open
# 使用独立数据目录
.\checkin-server.exe -listen 127.0.0.1:18990 -data E:\checkin-data
```

桌面版与服务版不能同时使用同一数据目录。再次启动桌面程序会尝试显示已有桌面实例。

账号列表每页渲染 50 项，表单保存期间锁定输入；桌面设置每 30 秒刷新。新会话保存限制为 2 MiB / 2048 个存储项。站点 / 账号创建与备份恢复共用 1000 / 10000 条上限；备份最多包含 100000 条结束记录、32 MiB 明文，导出前和采集过程中检查，避免生成无法恢复的文件。历史超量数据仍可读取，需整理至限制内再导出。

站点返回的 Retry-After 会保存为账号的最早执行时间，最长按一天处理；跨日、重启、修改计划或保存登录均保留此限制。自动计划落在可用窗口，手动签到也不能提前越过冷却时间。HTTP 任务共用有界连接池，各账号仍使用独立 Cookie jar；空闲连接最多保留 60 秒。

## Docker

```bash
docker compose up -d --build
docker compose exec checkin sh -c 'cat /data/access.token'
```

打开 `http://127.0.0.1:18990`，输入上一步在运行设备上读取的管理访问令牌。数据保存在 `checkin-data` 命名卷。若需局域网访问，可在 `.env` 中设置 `CHECKIN_BIND_IP=0.0.0.0`；公网部署应由 HTTPS 反向代理提供入口。

容器包含 Chromium，人工登录通过管理页面完成，无需开放 CDP/VNC。已通过 GitHub 中的实际容器启动、Chromium 登录/签到和重启持久化测试，详细记录见 [进度与验收](docs/progress.md)。

`docker compose` 本地构建使用 `auto-check-in:local` 标签；程序内的版本来自统一版本文件，发布镜像使用对应 Release 标签。

## 构建与测试

本次实际使用 **Go 1.27.3**，用于修复证书信任问题 GO-2026-6809，并由 CI 的 govulncheck 检查可达漏洞。`go.mod` 固定 `toolchain go1.27.3`。前端使用 Node 24、Vue 3、TypeScript 5.9；TypeScript 版本与当前 vue-tsc 配套锁定。

GitHub Actions 的 Linux 运行器明确固定为 **`ubuntu-26.04`**，避免 `ubuntu-latest` 迁移时自动切换环境。Docker 运行时使用独立固定的 Debian 基础镜像。

```powershell
# Windows：完整构建、测试、打包
.\scripts\build.ps1

# 单独开发
cd web
npm ci
npm run build
cd ..
go test ./...
go run ./cmd/server -data ./data -open
```

Windows 资源使用已固定的 GoVersionInfo 1.7.0 生成，不需要另装 MinGW。已经生成的 `build/windows/app.ico` 可直接使用，只有重新生成图标才需要 Pillow。

```powershell
# 浏览器隔离与资源池的真实 Chromium 测试
$env:CHECKIN_BROWSER_TEST = '1'
go test -race ./internal/...
go vet ./...

# 网页端到端测试：先构建 dist/checkin-server.exe
cd web
npm run test:e2e
cd ..

# 实际 Windows 窗口、托盘和开机开关测试
node scripts/native-smoke.mjs
```

`native-smoke` 使用隔离的启动配置文件；真实注册表适配器单元测试使用专用测试键，不修改实际开机运行项。
