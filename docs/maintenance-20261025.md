# 2026-10-25 修复、优化与维护

源码版本 1.0.7。更新 main，不创建 Release 标签。数据库格式 v6，支持现有 v5 在事务内升级；备份格式继续使用 v1。用户数据、密钥和备份不属于文件清理范围。

## 修复

| 问题 | 最终行为 |
| --- | --- |
| 网页按钮的有效密码会话跳过登录页后仍查找输入框 | 可选 PageSession 只读探测签到页面，已可操作时直接复用；只在明确登录表单或配置入口出现时登录 |
| 登录响应已确认但 SPA 跳转中止签到导航 | 对只读签到页面导航最多三次有界重试，不重放登录、授权或签到点击 |
| 泛用网页流程的身份漂移 | 复用与点击前核对页面绑定身份；新登录响应身份不符时在点击前停止 |
| 跨日 Retry-After 被次日随机计划覆盖 | 保存独立 retry_not_before；重启、改计划、保存登录、备份恢复、入队与领取均遵守冷却下界 |
| 备份能导出却无法恢复 | 创建、导出和恢复使用统一数量策略；导出前验证完整恢复契约，采集期间按序列化大小拒绝超量数据 |
| 登录路径含查询参数时 OAuth 入口误判 | 导航保留查询参数，页面判断及登录响应监听比较解析后的 pathname |
| 切换页面时丢失慢写入请求的刷新通知 | 写入完成由应用统一接收，移除各视图重复的刷新事件；输入与只读导出不触发刷新 |
| 密码登录等待读取被页面切换中断 | 只读表单检测可跨导航继续，邮箱入口检测和单次点击分离，不在轮询条件中提交动作 |
| 领取期间隐式重排后仍等待旧定时器 | 提交后的队列代次通知调度器重新计算等待时间，空闲时不增加轮询 |

冷却落在首次窗口内时仍可使用剩余窗口；落在窗口外时顺延后续窗口。冷却期间手动签到也被拒绝。v5 升级从近期结束记录恢复尚有效的限流，失败整体回滚；已有密文凭据不重新加密。

结果写回失败转为待核对时仍保留已知 Retry-After；恢复队列只写本地结果，不重放站点操作。

## 资源与模块

- domain 统一容量策略：1000 站点、10000 账号、100000 条结束记录、32 MiB 备份明文，48 MiB 备份文件；会话继续限制为 2 MiB / 2048 个存储项。
- 备份在单一事务中关联读取账号与密文，移除逐账号 SQL 和重复账号切片；错误口令和超量条数提前拒绝，旧超大凭据仍可读取，导出时明确提示整理。
- HTTP 连接池由 bootstrap 创建和关闭，最多 16 个空闲连接、每主机 2 个、空闲 60 秒释放。每个账号独立 Cookie jar 与认证头，单账号关闭不回收其他任务的连接。
- 账号、站点和设置支持 ETag / 304，客户端只缓存当前登录内的三个快照，退出或令牌变化即清空；连接代次阻止旧响应写回。账号 ETag 包含北京时间日期，跨日重新解析数据。
- 数据库建库 / 升级、调度落点、传输工厂、快照响应分别独立成模块；新增扩展能力保持可选，不要求 HTTP 会话依赖 DOM。
- 为历史状态和动作筛选增加有序索引；账号搜索词和异常计数使用计算属性，减少重复遍历。
- golang.org/x/net 升级至 v0.60.0，修复前轮扫描的五条模块级漏洞通告。
