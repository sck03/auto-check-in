# 运行与维护

## 数据目录

桌面版和独立服务默认使用**可执行文件旁的 `data`**，与启动时的工作目录无关。例如 `E:\AutoCheckIn\AutoCheckIn.exe` 使用 `E:\AutoCheckIn\data\checkin.db`。Docker 继续通过环境变量使用 `/data`。设置页“运行环境”显示实际绝对路径。

默认目录必须可写；写入失败会明确报错，不会转移到系统盘。使用 `go run` 开发时请显式传入 `-data ./data`，避免使用临时可执行文件旁的目录。

本版使用新的空数据目录重新安装，不兼容旧数据库或旧模板配置，不再从系统缓存目录导入数据。可通过 `-data` / `CHECKIN_DATA_DIR` 指定新目录。同版本的数据库支持正常重开和加密备份恢复。

重新安装或移动可执行文件后，如需开机运行，请在新程序设置中重新启用。

| 文件/目录 | 用途 |
| --- | --- |
| `checkin.db`、`-wal`、`-shm` | SQLite 数据与事务日志 |
| `master.key` | 本实例 32 字节主密钥的 Base64 表示 |
| `access.token` | 管理界面访问令牌；由环境变量提供时不生成此文件 |
| `desktop.json` | Windows 托盘偏好，与数据库备份分开 |
| `endpoint.json` | 当前实例的本机管理地址，供重复启动恢复窗口 |
| `instance.lock` | 进程独占锁，不要通过删除文件绕过运行中的实例 |
| `temporary` | 后台浏览器池及独立登录窗口的临时目录，会话结束或进程回收时清理 |
| `desktop-browser` | 独立管理窗口的临时浏览器配置，启动前回收旧组件，关闭窗口或收起托盘后删除，不存放站点账号会话 |

主密钥和数据库都在运行设备。数据库单独泄露不会直接暴露凭据；能读取主密钥与数据库的同一操作系统用户仍可解密。请将程序放在个人可写目录，Windows 文件权限继承所在目录。密钥丢失时拒绝创建新密钥覆盖已有数据库；使用 `CHECKIN_MASTER_KEY` 的实例迁移后仍需提供同一密钥。

## 环境变量

| 名称 | 默认 | 说明 |
| --- | --- | --- |
| `CHECKIN_DATA_DIR` | 可执行文件旁的 `data` / 容器 `/data` | 数据目录；`-data` 参数优先 |
| `CHECKIN_LISTEN` | `127.0.0.1:18990` | 服务监听地址；桌面版使用临时 loopback 端口 |
| `CHECKIN_ACCESS_TOKEN` | 自动生成 | 至少 32 个无空白字符；不要使用示例常量作为生产令牌 |
| `CHECKIN_MASTER_KEY` | `master.key` | 32 字节 Base64；更换会使旧凭据无法解密 |
| `CHECKIN_BROWSER_PATH` | 自动发现 | Edge / Chrome / Chromium 完整路径 |
| `CHECKIN_PROXY_URL` | 无 | 无账号密码的 HTTP / HTTPS / SOCKS5 代理 |
| `CHECKIN_ALLOW_HTTP` | `false` | 仅在明确需要连接 HTTP 站点时启用 |
| `CHECKIN_BROWSER_NO_SANDBOX` | Windows false，Docker true | 容器默认非 root 并由容器隔离，Chromium 使用此选项 |
| `CHECKIN_ALLOWED_ORIGINS` | 同源 | 可选的额外管理页面来源，逗号分隔 |

`CHECKIN_DESKTOP_TEST_PORT` 和 `CHECKIN_TEST_STARTUP_FILE` 仅用于自动化测试，不应配置到日常部署。后台自动执行使用管道；Windows 人工登录和管理窗口使用独立的本机随机调试端口，不接入日常浏览器配置，也不通过服务 API 暴露调试连接。

## 每日执行

所有计划统一北京时间。默认首次窗口 08:00–09:00，每个账号和每天独立确定时间，结束时间不包含在窗口内。调度器等待最近任务时间，配置、队列和系统时间通知即时唤醒；历史只在启动时和每天北京时间零点清理，没有每小时维护。系统恢复后重新核对当日计划；网络、同站点间隔和队列可能让实际开始稍晚，越过窗口的未开始任务顺延。完成后不持续访问站点，但常驻服务仍保留少量内存；收起到托盘会释放管理窗口浏览器，并停止窗口检测和定时菜单刷新。

默认补签与正在执行的自动任务也在 09:00 截止，失败后的状态复核不会另行延长截止时间。手动操作不受自动窗口限制，已确认成功的账号当天仍不能重复执行。

- 成功或已签到：当天停止，下次为次日随机时间。
- 明确临时失败：默认两次补签，约等待 5 / 15 分钟，加 0–30 秒扰动；尊重更长的 Retry-After。超过 09:00 不再自动尝试。
- 登录失效、密码错误、验证码：暂停，使用“浏览器登录”或编辑凭据处理。
- 操作结果未知、运行期间异常退出：暂停；New API 正常执行时先读状态，响应丢失后也尽可能读状态复核。缺少可靠状态接口时由用户核对后手动重试。

## 登录方式与授权

| 方式 | 使用方法与适用条件 |
| --- | --- |
| 浏览器会话 / Cookie | 恢复已有站点会话。会话过期后需要重新绑定；静态 Cookie 不会执行密码登录或 OAuth 重登录。 |
| 用户名与密码 | 填写站点的用户名或邮箱及密码。站点要求验证码或二步验证时，通过浏览器登录完成。 |
| GitHub 授权登录 | 保存账号后打开“浏览器登录”，程序自动选择 GitHub 入口，再完成首次登录及授权。 |
| Linux DO 授权登录 | 保存账号后打开“浏览器登录”，程序自动选择 LinuxDO 入口，再完成登录及授权。 |

账号的登录方式应与实际使用的方式一致。通过 LinuxDo 登录的账号应选择“Linux DO 授权登录”，不能依靠填写账号名称来决定授权方式。AgentRouter 的每日奖励依赖重新登录，应使用密码或 OAuth；静态 Cookie 查询不算签到。

AgentRouter 执行前仅清除本站会话，保留 GitHub / LinuxDO 登录和站点验证 Cookie，再点击配置的授权入口。自动执行只会继续已识别的官方授权表单，并核对回调 origin 或 OAuth 事务；不会重复点击授权。未完成的密码、验证码、二步验证以及无法识别的页面仍通过人工登录处理。选择器有多个候选、无效或页面已跳离本站时，不猜测点击其他登录方式。

无需提前在日常浏览器中登录 LinuxDo 或 GitHub；程序为每个账号保留独立会话。Windows 桌面版会直接打开独立浏览器窗口，输入、滚动、弹窗与正常浏览器一致。完成后回到管理界面点击“保存会话”。取消、关闭登录浏览器或过期都会结束此次会话。

保存会话和签到结束也会关闭该账号的全部页面与授权弹窗。后台进程空闲保留期间没有账号页面，不会持续登录、刷新或退出网站。若仍影响日常浏览器登录，需要结合站点的会话策略核对；独立目录不能改变站点限制同账号同时登录的规则。

Docker / 网页版仍在页面内提供浏览器预览。点击网页输入框后可以直接键入或粘贴，文字输入栏也可使用；OAuth 新开的页面会自动显示，关闭后返回原页。LinuxDo、GitHub 或站点的验证码、授权确认、账号限制仍按真实页面处理，看到验证页面不代表登录已成功。

窗口内重启仅补跑当日已到点任务；离线多天不会重放多天请求。失败次数从持久记录统计，重启不会刷新预算。手动执行可在窗口外发起；已经确认成功的账号当天仍会拒绝再次执行。

## Windows 托盘与开机运行

默认启用“最小化到托盘”和“关闭窗口后继续运行”。收起窗口会关闭显示用的浏览器进程，Go 服务、调度和托盘继续运行；恢复时重新打开同一管理实例。后台签到浏览器池与管理窗口独立。

管理窗口不需要 Edge 的购物、钱包、媒体和组件模型下载，因此仅此窗口禁用组件更新、后台联网、同步及扩展，限制磁盘缓存目标为 8 MiB、媒体缓存为 1 MiB。浏览器自身配置仍会占用额外空间，不能将缓存参数视作整个目录的硬上限。窗口结束后等进程退出再回收目录；遇到短暂文件锁最多重试 3 秒，下次打开还会再次清理遗留目录。账号数据库、密钥和独立登录窗口不受管理窗口清理影响。

“登录 Windows 后自动启动”只操作当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中 `AutoCheckIn` 项，保存本程序绝对路径、`-background` 和数据目录。无需管理员权限。它不是关机期间执行的系统服务，也不保证未登录 Windows 时执行。移动程序路径后应重新开关一次开机运行选项。

托盘菜单可显示主窗口、运行全部账号、暂停/恢复计划、切换三个桌面偏好、打开数据目录和退出。退出会等待当前操作取消、写回记录、关闭浏览器和数据库。偏好文件写入失败时回滚本次自启动注册修改。

## 备份与恢复

设置页导出 `.backup` 文件，使用至少 12 个字符的口令。格式为版本化 JSON 信封、随机盐、PBKDF2-HMAC-SHA256（600000 次）派生密钥和 AES-256-GCM 密文。备份可在新设备、新主密钥下恢复，不依赖原 `master.key`。

备份包含站点、账号凭据、计划、全局设置及已结束的记录。备份时仍在运行的账号恢复为待核对状态，不重放未知操作。Windows 开机运行注册、托盘偏好、管理令牌和浏览器缓存不作为跨设备账号备份迁移。

恢复仅允许没有账号的新实例，全部写入在事务中完成。错误口令、损坏文件、无效引用不会部分写入。恢复后自动计划暂停，请核对配置后再启用。

如直接复制数据目录，请先完全退出程序，并一并保存数据库及主密钥；运行中不能只复制 `checkin.db` 而遗漏 WAL。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 访问令牌无效 | 在运行设备读取 `access.token`，或使用实际设置的环境变量令牌 |
| 无法解密账号 | 恢复原主密钥；不要删除密钥重新生成 |
| 数据目录被占用 | 从托盘退出已有实例；服务版与桌面版使用不同目录 |
| 数据库版本不兼容 | 使用新的空 `data` 目录重新配置，或通过 `-data` 指定新目录 |
| 浏览器未检测到 | 安装 Edge/Chrome/Chromium 或配置完整路径，然后重启 |
| 浏览器会话达到上限 | 完成或取消已有人工登录；后台任务与人工登录合计最多两个会话 |
| AgentRouter 没有奖励 | 检查登录方式及记录中的 checked_in 证据；静态 Cookie 查询余额不等于签到 |
| 已登录仍显示待确认 | 旧操作结果未知不会因保存登录而自动改为成功；核对站点后手动重试 |
| 随机时间到了没有执行 | 检查程序、全局计划、账号开关、同站点队列及时间窗口 |
| 09:00 后失败未补签 | 已超过补签窗口，正常顺延到次日 |
| Docker 卷不可写 | 命名卷使用镜像内 UID 10001；绑定主机目录时为该 UID 配置写权限 |

## Docker 运行验收

```bash
docker compose config
docker compose up -d --build
docker compose ps
docker compose exec checkin checkin-server -healthcheck
docker compose logs --tail 50
docker compose restart
```

检查管理界面、账号持久化、人工浏览器登录、重启后的时间与次数。不要删除命名数据卷来“修复”登录问题。
