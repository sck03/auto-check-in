## 本地验收结果

2026-10-19 追加修复：AgentRouter 在 `/api/status` 返回前就显示可点击的 OAuth 按钮，过早点击会发送 `client_id=undefined`。现在等待账号对应的应用 ID 就绪后再点击；LinuxDO 的“允许”链接需匹配官方审批地址及同一授权面板内的本站应用地址。桌面 AgentRouter 使用普通独立窗口，并在快速授权弹窗开始执行前准备响应监听，避免漏掉已授权账号的登录回调。

人工登录与自动执行共用本站会话清理，保留身份提供方及验证 Cookie。`/console/personal` 是个人设置页面，实际用户信息接口仍是 `/api/user/self`；实测后者可能返回 HTTP 200 的阿里云 WAF HTML。保存时优先使用本次成功登录响应，并核对当前页面用户 ID 与会话 Cookie，避免已登录却保存失败；旧缓存或不一致的身份不会被当作成功。

已用用户授权的本地账号完成两种方式的真实自动重新登录，GitHub 约 12 秒、LinuxDO 约 12 秒，均收到 `/api/oauth/{method}` 的成功响应并取得新会话；结果包含站点签到确认，不以页面跳转或余额变化代替。Windows 原生回归覆盖两种方式、同页/弹窗、连续两次独立新登录、普通交互输入和用户信息查询受拦截。没有新增运行依赖，诊断代码已移除。

按用户要求，只有 AgentRouter 每次清理本站会话；其他站点优先复用有效会话。补充 AnyRouter / New API 真实浏览器回归后，修复了已确认 401 失效时旧页面用户标记仍把登录页跳回控制台的问题：仅在重新登录前移除此失效标记，Cookie 保留。有效会话没有登录请求，失效后各只发起一次 LinuxDO 登录。

更新后的 Windows 成品已实测：LinuxDO、GitHub 均自动完成授权并成功保存会话；LinuxDO 的完整签到执行记录为 `succeeded / provider_acknowledgement`。GitHub 账号原本停用，保留该状态，程序按预期拒绝将其加入执行队列；其自动新登录成功来自前述独立执行器实测。真实账号凭据与记录不进入仓库。
